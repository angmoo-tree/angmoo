# Chat·SNS의 시작 입력과 현재 실행 권한

2026-10-29 PostgreSQL 격리 실험의 입력 계약이다. main 반영·정식 배포·휴대폰 수용 완료를 의미하지 않는다.

## 판단 단위

Chat 응답 슬롯 한 개와 Inbox·Feed·Routine의 개별 판단은 처음 확보한 참고 입력을 사용한다. 관계 수치와 인식, 이미 읽은 글·댓글·대화, 오늘 SNS, 검색한 상황기억의 요약·순위·원문 스냅샷, 표시 이름과 프로필·일상 계획의 내용 변경 때문에 같은 판단을 다시 생성하지 않는다. 다음 독립 요청·판단은 최신 자료를 읽는다.

AI 응답을 기다리는 동안 DB 트랜잭션을 유지하지 않는다. 최초 조회와 저장, 현재 실행 권한 확인, 결과 쓰기는 각각 짧은 DB 작업으로 수행한다.

## 보존 위치와 재개

- Chat은 기존 응답 request의 `node_state`에 `chat-initial-input.v1` 자료를 저장한다. 응답 슬롯·scope hash·owner/World/thread/참여자에 연결하고 JSON 크기를 구성요소별 512 KiB로 제한한다. 자료와 SHA-256을 함께 확인한다. 자격 증명은 이 입력에 넣지 않는다.
- 라우팅 결과와 `social_hybrid` 최초 검색 결과도 타입이 정해진 별도 구성요소로 저장한다. 같은 슬롯의 명시적 재시도에서는 요청 ID만 새 실행에 연결하며 라우터·임베딩·검색을 반복하지 않는다. 현재 기억 사용권은 다시 확인한다. 검색을 시작했지만 최초 결과를 보존하지 못했다면 그 상태를 명시적으로 거절하며 최신 검색으로 빈 자료를 채우지 않는다. 아직 시작하지 않은 단계는 첫 입력을 정상적으로 확보한다.
- 기존 LEGACY GRAPH/BOTH 경로에서 이미 시작한 검색의 재개 자료가 없으면 `chat_initial_recall_unavailable`로 종료한다. 이 실험의 기본 `social_hybrid`에서는 해당 두 경로를 제공하지 않는다. 최초 LEGACY 호출과 과거 기록의 호환성은 별도 계약이다.
- Router가 유효한 결과를 만들지 못해 스키마 검증·수리를 소진했다는 확정 기록이 있으면, 사용자가 요청한 재시도에서 보존된 최초 입력을 다시 해석할 수 있다. 중단으로 결과 존재 여부를 모르는 경우에는 이 예외를 적용하지 않는다.
- 라우팅 시작·결과 또는 이전 정책의 입력 소비 기록은 있는데 최초 입력 묶음이 없으면 현재 자료를 다시 읽어 채우지 않는다. 명시적 재시도에도 이 누락 상태를 전달해 AI 호출 없이 종료한다. 아직 참고 입력을 확보하지 않은 최초 준비 단계의 실패와 구분한다.
- SNS는 기존 후보·shared/decision context·검색 결과·checkpoint와 provider recovery ledger를 사용한다. `social-context-initial-input.v1`은 참고 내용과 범위를 검증하고 현재 관계값의 일치 여부를 요구하지 않는다. 후보 준비 뒤 Inbox가 완료돼도 Feed의 이미 확보한 참고 자료를 교체하지 않는다.
- Routine은 읽기용 필드만 저장한 값 객체를 사용한다. beat·claim·공개 결과는 현재 DB의 소유 레코드로 처리한다. 원래 글이 삭제됐더라도 이미 읽은 참고 본문을 재조회하지 않는다.
- 과거 `social-context-currentness.v1` 및 legacy 정책 기록을 새 정책으로 추측해 고치지 않는다. 기존 입력을 복원할 자료가 없는 checkpoint는 실패 사유를 남긴다.

## 유지하는 검사

현재 소유권·World 및 캐릭터 상태·차단·기억 사용 동의·명시적 기억 삭제·유효 기간·삭제 의존성·실제 답글 대상과 답글 허용 여부를 확인한다. 기억의 일반적인 수정으로 `superseded`된 자료와 명시적 삭제를 구분한다. 이미 검색한 기억의 원문 대신 현재 권한 메타데이터와 보존된 스냅샷 digest를 확인한다.

취소·기한·실행권·idempotency·동일 행동의 중복 방지·결과 쓰기의 CAS 및 트랜잭션 원자성도 유지한다. 참고 입력이 고정됐다는 이유로 현재 관계나 활동 상태의 변경을 과거 값으로 덮어쓰지 않는다. 상태 반영의 `conflict_not_applied`는 실제 공개 행동의 성공과 구분한다.

상황기억에는 모델에 실제로 전달한 부분만 원문 스냅샷으로 남긴다. 여러 글이 합쳐진 입력이나 길이 제한으로 일부만 전달된 입력에서는 각 원문의 전달 범위를 구분한다. 관계 검토의 입력은 계속 상대별 **상황기억 본문 + 기존 방향별 관계 인식**이며, 원문 스냅샷을 넣지 않는다.
